# Milestone 4 notes

[← back to PROGRESS.md](../../PROGRESS.md)

- `server/src/lib/index/db.ts` — schema (`projects`, `tasks`, `journal_entries`, `journal_task_links`, `index_meta`, per PLAN.md's sketch) + `openIndexDb`/`deleteIndexDb`, opened in WAL mode. All `node:sqlite` access stays isolated to this one file, per PLAN.md (it's still Node-experimental).
- `server/src/lib/index/reindex.ts` — `reconcileWorkspace` walks `projects/*.md` and `journal/<year>/*.md` doing `readdir`/`stat` only, and reparses a file only when its `mtime` differs from what's stored (a deliberate stat-diff, not a content-hash compare — a hand-touched file with unchanged content still gets reparsed, matching PLAN.md's "compare mtime/size" reconciliation strategy exactly). `source_hash` (sha256) is stored alongside for future use but isn't itself the staleness signal. Index rows for files no longer on disk are deleted every pass. `rebuildIndex` (backing `POST /api/index/rebuild`) deletes the sqlite file (+ WAL/SHM sidecars) and reconciles from scratch — the "hard portability constraint" that deleting the index must always reproduce identical state from a clean scan. `getIndexStatus` backs `GET /api/index/status` (last-reconciled timestamp + row counts).
- `server/src/routes/index.ts` — thin `POST /api/index/rebuild` / `GET /api/index/status`, both resolving the active workspace via `services/workspaces.ts`.
- Files that don't match the expected naming pattern (anything except `<slug>.md` directly under `projects/`, or `YYYY-MM-DD.md` directly under `journal/<YYYY>/`) are silently skipped rather than erroring — this is what makes sync-conflict artifacts (`task-list (conflicted copy ...).md`) harmless, per PLAN.md "Remote & cloud sync".
- Deliberately *not* wired into `addWorkspace`/`openWorkspace` yet (unlike `vaultGit.ts`'s `ensureGitHistory`) — non-blocking startup reconciliation depends on the aggregate routes (milestone 9) actually existing to need it; wiring it in now would just mean every workspace open does a full synchronous parse for no consumer. Revisit when milestone 7-9 land.
- Verified: `npm test -w server` (`reindex.test.ts`) covers row-for-row matching, a no-op reconcile reparsing nothing, touching one file's mtime reparsing only that file, a removed file dropping its rows, and rebuild-after-delete reproducing identical counts. Also verified live over HTTP (see Milestone 5 notes above, which shares the same scratch workspace) — `POST /api/index/rebuild` against seeded project+journal files produced the expected `projectCount`/`taskCount`/`journalEntryCount`, and deleting `.pivot/cache/index.sqlite3` and rebuilding reproduced identical counts.
