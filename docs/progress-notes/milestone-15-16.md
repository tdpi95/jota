# Milestone 15 & 16 notes

[← back to PROGRESS.md](../../PROGRESS.md)

- Built together in one pass — both are thin frontend-only additions over routes/services that already existed complete (vault history/diff/revert from milestone 5, workspace add/open/remove from milestone 2, remote sync from milestone 6), so there was no backend work to split out.
- **`HistoryPanel`** (`client/src/components/HistoryPanel.tsx`): takes a `path` (relative to the workspace root — `projects/<slug>.md` or `journal/<year>/<date>.md`, the same convention `services/{projects,journal}.ts` use internally) and an `onReverted` callback, and is otherwise self-contained — it owns its own `GET /api/vault/history?path=` query, an expand-to-diff toggle per row (`GET /api/vault/diff/:commit`, fetched lazily only once expanded), and a one-click Undo (`POST /api/vault/revert/:commit`, `window.confirm`'d first, same pattern as the existing task-delete confirm). It has no way to know which *other* queries a revert on its file affects (a project's task columns, a journal entry's body/tags, the calendar's dots) so that's left to the caller via `onReverted` — wired into `ProjectDetailPage` (reuses the same `invalidateProject` its own mutations already call) and `JournalDayPage` (a new `invalidateEntry`, which refetches rather than `setQueryData`s the entry — unlike the page's own save/link mutations, a revert changes the file out from under the client without handing back the new shape).
- **`WorkspaceSwitcher`** (`client/src/components/WorkspaceSwitcher.tsx`) replaces `AppShell`'s old read-only workspace display: a dropdown button showing the active workspace, listing every registered one (checkmark on the active, click to `POST /api/workspaces/:id/open`), and "+ Open folder" wired to `window.pivot.pickFolder()` (milestone 3's native picker) → `POST /api/workspaces {path}`. Switching or adding a workspace can change literally everything on screen (every project/task/journal/calendar query is scoped to "the active workspace"), so — uniquely among this app's mutations — its `onSuccess` calls `queryClient.invalidateQueries()` with no key, invalidating the entire cache, rather than picking specific query keys the way every other mutation in this codebase does.
- **`client/src/lib/pivotBridge.ts`** — a hand-duplicated copy of `electron/src/preload.ts`'s `PivotBridge`/`ReminderSettings` types (same reasoning as `client/src/types.ts` duplicating server types: `electron/` and `client/` are separate npm workspaces/tsconfigs) plus `getPivotBridge()`, which returns `window.pivot` or `null`. Every caller goes through this and branches on `null` — `window.pivot` only exists inside the Electron shell, so a plain browser tab (opening the Vite dev server directly, without Electron) gets a graceful fallback rather than a crash: `WorkspaceSwitcher`/`SettingsPage` fall back to a plain text-path input for "open folder" (mirroring `design/Main.dc.html`'s own pre-Electron-decision `ws-open-new` affordance), and the reminder-time/launch-at-login controls are hidden entirely rather than shown non-functional.
- **`SettingsPage.tsx`** (full rewrite of milestone 3's placeholder): a Workspaces section (`ws-rows-list` — name/path, Open/Active button, a remove icon-button with `window.confirm`, "+ Open folder" or the manual-path fallback below the list); a Remote sync panel per PLAN.md (`GET/PUT /api/vault/git/remote`, `GET /api/vault/git/status`, Push/Pull buttons, ahead/behind counts, last-synced time, and — beyond PLAN.md's literal list but implied by "conflict list if any" — a conflict-file list rendered from a Pull's `{conflict:true, files}` response, which is local component state rather than persisted anywhere since it's just the outcome of the last pull attempt); and, only when `getPivotBridge()` is non-null, a Daily reminder field (checkbox + `<input type="time">`) and a Launch-at-login checkbox, both calling straight through to `window.pivot.{get,set}ReminderSettings`/`{get,set}LaunchAtLogin`.
- **The reminder field is built ahead of its backend** (deliberately, matching PLAN.md's own milestone split: 16 is the frontend control, 17 is `reminder.ts`'s scheduler and the backing per-workspace `reminderTime` data model) — `getReminderSettings`/`setReminderSettings` are declared in `preload.ts` per milestone 3 but have no `ipcMain.handle` registered yet, so the initial load call always rejects today. `SettingsPage` catches that and falls back to `DEFAULT_REMINDER = {enabled: true, time: '20:00'}` (PLAN.md's own stated default for a newly-added workspace) so the control is usable/testable now rather than showing nothing; a save-time rejection (once there *is* a handler, any transient IPC failure) surfaces as an inline "Couldn't save reminder settings." rather than failing silently. Launch-at-login has no such gap — its `ipcMain.handle` has been live since milestone 3 — and was verified actually round-tripping through a stubbed bridge (see below).
- Remote-URL save is on blur/Enter rather than a separate Save button — no separate button appears in `design/Main.dc.html`'s own sync-panel markup, and it keeps the field consistent with how the rest of the app treats a single text input (`TagInput`'s own commit-on-blur, for instance).
